# Handoff

## State
`onRetry` option added (index.js, readme.md, test.js). `npm test` (xo, node --test, nz) passes. Not committed.

## Decisions
- `onRetry(context)` runs in `onAttemptFailure` after `onFailedAttempt`, `shouldConsumeRetry` and `shouldRetry`, and after the final maxRetryTime check, right before the wait. That is the first point where another attempt is certain, so the final failure is never counted.
- It gets the same frozen `context` as `onFailedAttempt`.
- It also runs when `shouldConsumeRetry` returns false: another attempt does happen, just with no wait.
- Signal is re-checked after it, like the other callbacks, so the delay's abort listener is not skipped.
- Throwing or rejecting aborts retries, as for the other callbacks.

## Failed approaches
- First test for the non-consumed retry used `retries: 0`; that throws before any retry, so it needs `retries: 1`.
- Put `onRetry` typings in index.d.ts and a type test in index.test-d.ts at first; reverted. In this fork index.d.ts is generated by the types-sync job from the schema in platform-types, and CI fails on hand edits. Never edit index.d.ts; no type tests for options not yet in it. The user adds `onRetry` to the schema themselves (its JSDoc text is in the readme section).

## initialDelay (added after onRetry)
State: `initialDelay` implemented in index.js, readme.md, test.js; `npm test` passes. Not committed. index.d.ts untouched, per the rule above; the user adds `initialDelay` (number, default 0) to the schema.

Decisions:
- Waits via `delayForRetry` after option validation and the initial signal check, before `startTime` is taken, so `maxRetryTime` does not count the wait. Abort during it rejects with `signal.reason`; `unref` and the timer cap apply.
- Skipped entirely when `initialDelay` is 0 (no `await`).
- Validated like `minTimeout` (finite number, >= 0); `null` means default.

Failed approaches:
- Awaiting `delayForRetry(0)` unconditionally returned early but still cost a microtask, so an abort fired synchronously after calling `pRetry` landed before the first attempt (broke 'an abort does not interrupt an attempt that is already running'). Hence the `> 0` guard.
- First test measured the wait with `Date.now()`; `withFakeTime` only moves `performance.now`, so use its `delays` and `now()`.
