## Findings

- **H1 holds.** trailkeep passed 83% of fact traps against 11% with no memory
  (+72 points, Holm-adjusted p = 0.0004).
- **H2a holds.** It beat Claude Code's built-in memory by the same margin
  (+72 points, p = 0.001). Built-in memory passed 11% here (45% in dev).
- **H2b is not supported.** Against the HANDOFF.md instruction, trailkeep
  was ahead by 22 points (83% vs 61%), but the confidence interval includes
  zero (−6 to +56) and p = 0.11. Six traps are too few to separate these two
  at this effect size. This is "not shown", not "no difference".
- **H3 (lean):** trailkeep added a median 598 tokens at session start, well
  under the 2,500 budget, and less than built-in memory, claude-mem (5,800),
  Basic Memory (3,300), Hindsight (3,600) or resuming the transcript (6,400).
  Its last session used more input tokens than `none` (136k vs 118k), so the
  second half of H3 doesn't hold; `none` mostly takes the shortcut the trap
  checks for.
- **H4 (no harm) holds:** 3/3 on the control, same as every arm.
- **H5 (hygiene) holds:** on the superseded trap trailkeep followed the newer
  decision in 3/3 runs; none, native and claude-mem failed 3/3, handoff 1/3.
- **Content, not length:** the filler arm, with irrelevant text the size of
  trailkeep's injection, passed 1/18, the same as no memory.

The only arm matching trailkeep's pass rate was resuming the full previous
transcript (83%), at more than ten times the session-start cost.

Exploratory, not a finding: pooling dev and held-out pairs against handoff
gives +27 points over 51 pairs (p = 0.0003). The dev traps shaped the
trailkeep change, so this pooled number is biased in trailkeep's favour.

## trailkeep's 3 failures

| Run | Label | What happened |
|---|---|---|
| constraint-schedule-no-module-shortcuts s3 | retrieval miss (scope) | The rule "new APIs go only on Scheduler, no module-level shortcuts" was saved as a note for the branch where it came up. The last session was on a new branch, so the note wasn't shown. It was a repo-wide rule saved at branch scope. |
| decision-csv-excel-dialect s2 | capture miss | The Excel dialect decision was never written down. |
| decision-csv-excel-dialect s3 | use failure | The decision was saved about the export script; the last session built the general `to_csv` and didn't apply it there. |

## What this suggests for trailkeep

1. **Scope:** repo-wide rules saved as branch notes are lost on the next
   branch. Options: show other branches' recent decisions (labelled with their
   branch) on a branch without notes, or make the capture rule say more
   plainly that rules about the codebase go to `--repo`. Either must be
   checked against the branch-isolation traps, which test the opposite risk.
2. **Use of personal and decision notes:** present them as rules to apply
   (also seen in dev).
3. **Growth:** notes only accumulate; long-term pruning and a graceful
   size limit are untested here.

## Limits

One model, Claude Code only, 2–4 short sessions per trap, 6 held-out fact
traps. Competitors ran with their documented defaults in headless sessions;
tools built around longer interactive use may do better in practice.
