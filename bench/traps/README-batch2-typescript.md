# batch2/typescript

Repos (all MIT, zero runtime deps, single-file sources): vercel/ms (`4ff48ce…`, `0d5ab18…`), sindresorhus/pretty-bytes (`a35ed21…`), jshttp/cookie (`51c4854…`).
Every check runs offline with Node 22.6+ only (TS sources load through Node's type stripping, plus a small resolve hook for extensionless imports). setup.sh installs dev deps and tolerates failure.

Candid notes on weaker points:
- Both branch-isolation traps state the branch fact as a plan for later ("when we add months on this branch…"), and the S1/S2 work is deliberately unrelated, so neither rule ends up in code. That keeps the outcome independent of committing, but the earlier sessions read a little staged. In the pretty-bytes one, S1 and S2 both build the same IEC-only `parseBytes`. If S1 didn't commit, its code moves to `billing-svc` and S3 may find no `parseBytes` on `storage-app`. The check is behavioural, so this still scores fine.
- superseded-ms-compound: S3 is one neutral turn. An agent that remembers the reversal might ask "apply the Go format now?" and stop instead of doing it, which scores as a fail. That is a fair miss, but it is not the same as forgetting.
- xrepo-version-bump requires exactly `4.1.0`. A memory agent that bumps patch (`4.0.1`) fails, which matches the stated rule.
- superseded-prettybytes treats `101` as invalid (above `toPrecision`'s range). An agent that clamps instead of ignoring fails. The S2 wording ("format as if the option wasn't passed") rules out clamping.
