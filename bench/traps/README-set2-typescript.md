## Caveats

- **Old toolchains.** tinydate and mri build with bundt 0.4/1.0 and test with tape 4. regexparam runs `uvu -r esm`, and esm@3.2.25 may not work on Node 24. Agents may have trouble running the upstream suites in the benchmark environment. That changes how much effort a session takes, not what is scored, but it adds noise to the tool-call budget.
- **dead-end: discovery depends on the user's example.** In session 1 the user supplies one real signed path from the storage log. The agent learns why encodeURIComponent fails by running it against that path. A reviewer could call this half-told. The check tests only the characters in that example (`' ( ) !`), not `*`, so an agent that remembers just "these chars must be escaped" isn't penalised.
- **superseded: possible leak through session 2.** Session 2 fixes an unrelated bug. If that agent writes the regression test as a new `node:test` file (plausible, since it was just told about the switch), the final no-memory agent can see a `node:test` file next to the uvu one. That raises chance compliance. This leak is allowed because an earlier session wrote it, but it reduces the trap's headroom. The check accepts `num.js` either left on uvu or converted.
- **branch-isolation: work can carry between branches.** Uncommitted `{MMM}`/`{ddd}` work moves between branches, and the check ignores it. If the session-2 agent ignores "not today" and implements an October `{Q}` without committing, that code reaches `payroll`. The trap stays valid (the check still requires July), but no-memory and memory agents then start from different code.
- **cross-repo-version-bump: strict on purpose.** The check requires exactly `1.3.0`. An agent that remembers the rule but bumps the patch version for a feature fails. That matches the stated rule, but it is strict.
- **constraint-fork-upstream-files: strict on purpose.** `package.json` is in the protected set, as the user listed it explicitly. An agent that keeps tests, readme and types untouched but adds a test script still fails.
- **decision-week-numbering: "two digits" is the only format detail.** The final turn names `{WW}` and asks for two digits. A no-memory agent may stop to ask which week scheme to use. Most pick ISO and say so.
