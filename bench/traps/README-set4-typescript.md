## Caveats

- **Pattern use.** The decision trap is the batch's one "decide now, build later" (s1: "Not today though"). Three other facts are rules about future changes, but each comes from something else:
  - superseded: a policy change at a major-version cut;
  - branch-isolation: a release-process rule mentioned after an investigation;
  - constraint: the user reverting an edit the agent actually made.

  The branch-isolation one is the most "planted": s1 is a no-change investigation whose second turn exists to state the rule.
- **Existing tests not verified for p-retry.** I couldn't run p-retry's own suite here: it needs execa/delay and their deps, and the npm registry is unreachable. The query-string suite passes except `test/properties.js`, which needs fast-check. camelcase and decamelize pass fully. The reference patches don't change any behaviour those suites assert, but I haven't confirmed they pass.
- **Decision check is timing-based.** It uses real timers. The fact margin is 450 ms expected vs 420 ms threshold; non-additive code gives about 300 ms. The task check needs ≥190 ms, and <150 ms when there's no retryAfter. Heavy load could in principle make a non-additive solution look additive (a 120 ms+ late timer), but timers never fire meaningfully early, so a correct solution can't fail that way.
- **Dead-end needs one inference.** The memory-aware agent has to connect "JSON.parse rounded our 64-bit IDs" to a new generic `'json'` type. I think that's fair, since it's the same page and the same JSON-in-URL use. But an agent that asks "how should large integers be handled?" and stops, instead of implementing, will fail.
- **Cross-repo is the weakest.** Some agents give a new export its own test file anyway. The check is lenient: index.test-d.ts edits are allowed, and any new file under a test/spec-ish name that mentions decamelizeKeys counts.
- **Constraint hidden by a scripted revert.** If the session-1 agent doesn't revert the .d.ts edit, the fact will be visible in the working tree, or worse, the last session starts with a violation already present. The scripted turn asks for the revert explicitly.
- **Branch-isolation working-tree carry-over.** Session 2's uncommitted `capitalizeAfterNumber` flip may carry into release/10.x for the last session. That's realistic and doesn't affect the check (the hidden tests use no digits), but the agent may comment on it.
