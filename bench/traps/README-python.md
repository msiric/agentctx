# Python traps

- `decision-tinydb-yaml-bools` | decision | msiemens/tinydb@edff96a | YAMLStorage uses PyYAML with a loader where only true/false are booleans, so hand-typed `NO`/`yes`/`off` stay strings (no plain safe_load, no ruamel) | The docs (extend.rst) and the existing test_yaml both build a YAML storage with `yaml.safe_load`, so an agent copies that, and YAML 1.1 turns `NO` into False.
- `decision-schedule-reraise` | decision | dbader/schedule@82a43db | When a job raises, run_pending still runs the other due jobs and then re-raises the first exception, because the supervisor pages on crashes | "Make one failing job not kill the loop" usually ends up as catch, `logger.exception` and continue, which is also the docs' catch_exceptions recipe. That swallows the error.
- `deadend-tinydb-mtime-cache` | dead-end (told) | msiemens/tinydb@edff96a | Don't detect file changes by mtime/stat: on the NFS share mtime has 1 s resolution and an mtime cache already served stale data | "Skip re-parsing unless the file changed, other processes write it" almost always becomes an `os.stat` (mtime_ns, size) check, and that misses a same-second, same-size write.
- `deadend-tinydb-streaming-write` | dead-end (discovered) | msiemens/tinydb@edff96a | Streaming `json.dump` into the db file corrupts it when serialization fails partway (session 1 saw test_insert_invalid_dict fail). Serialize fully before touching the file | For a new GzipJSONStorage the idiomatic `with gzip.open(p, 'wt') as f: json.dump(data, f)` truncates first and then streams. An unserializable insert then destroys the db.
- `constraint-dotenv-no-values` | constraint | theskumar/python-dotenv@bad5771 | New CLI commands never print env values, only key names (secrets, public CI logs) | A `dotenv diff` naturally shows `KEY: old -> new`, and the existing `list`/`get` commands print values, so the repo suggests that printing values is fine.
- `constraint-schedule-no-module-shortcuts` | constraint | dbader/schedule@82a43db | New APIs go on Scheduler only, with no new module-level shortcut functions for the global default scheduler | Every Scheduler method has a `schedule.<name>()` wrapper, under a comment that says these are shortcuts, so an agent adding pause/resume adds `schedule.pause`/`schedule.resume` too. The last session runs on a fresh branch, so session 1's code is not in the tree.
- `control-dotenv-get-default` | control | theskumar/python-dotenv@bad5771 | (none: single session, `dotenv get --default`) | n/a. It measures overhead only. The trap patch is the common `values.get(key) or default` bug.
