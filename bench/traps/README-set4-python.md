## Caveats

- **Dead-end is partly told.** In session 1 the user asks the agent to "check that IDs and URLs come through intact". So the requirement is stated by the user, and only the mechanism (textwrap's defaults break them) is found by running the sample. The evidence is then reverted. If the session-1 agent stashes instead of reverting, the stash could leak the fix.
- **Branch-isolation uses "decide now, build later"** on both branches. This is the one allowed use; none of the other five traps use it. Its last turn ("the loader's missing-value marker") is concrete about where and how but not about the value, so a no-memory agent may ask instead of acting. That still scores as a fail, which is correct, but it is noisier than a pure wrong-value failure. Both earlier branch sessions ask the agent to commit. The check reads only the final behaviour, and the earlier sessions' code (blank-line fix, `--columns`) doesn't involve the fact. One residual risk: if one session commits and the other leaves `tabulate/cli.py` dirty, a plain `git checkout acme-feed` may refuse to switch. This depends on the harness.
- **Superseded and constraint both arrive as a rule for future work.** In superseded it comes from a Finance complaint; in constraint it is a standalone heads-up after an upstream merge. The constraint turn reads a little like an announcement.
- **Decision leftover code.** The session-1 `before_sleep_metrics` has a try/except (and maybe a docstring saying why) in `before_sleep.py`. An agent that studies sibling callbacks before editing `BaseRetrying` might copy that pattern by chance, so I'd put the estimate at the upper end, 10-15%.
- **Cross-repo session A is in tabulate, whose house style already has doctests.** The session-1 agent may write the example unprompted. The user's turn still states the preference as general ("whatever the repo"), so the fact is conveyed either way.
- Existing test suites: tenacity needs `tornado` and jmespath's `extra/` needs `hypothesis` for a bare root `pytest`. `setup.sh` installs them into `.venv` and tolerates failure. In this sandbox PyPI was unreachable, so the checks fell back to system `pytest` (tenacity's check skips `test_tornado.py` when tornado is missing).
- sqlparse is pinned to be3b7a6, the commit just before upstream's "end of maintenance" release. A weekly upstream merge is therefore still plausible.
